§ 01 · Protocol

Cut once. Held by both.

Historically, a tally stick was notched across the grain and split lengthwise so neither party could add a debt alone. Tally applies the same rule to signed bytes.

01 / Write1–140 UTF-8 bytes

State what the payment settles

The payer enters the recipient, the amount, and one plain line of text. Line breaks are rejected at consensus so a receipt cannot tuck a second clause below the fold. An optional 32-byte mark commits to an off-chain file, deliverable, or post.

02 / Signed25519 in browser

Lock the canonical lines

Your 32-byte seed stays in local storage and never touches the node. The browser hashes the memo into the notch and signs the eight canonical lines of tally.tx.v1. Altering one byte invalidates both the notch and the signature.

03 / VerifySHA-256 PoW

Read the same block back

A miner commits the transaction root into a proof-of-work block. When the payee opens the transaction link—today or a year later—their browser recomputes SHA-256(memo) and verifies the payer’s public key directly from the tally1 address.

§ 02 · Wire format

Eight lines, zero hidden state.

Every wallet, explorer tab and CLI node hashes the exact same UTF-8 byte sequence from client/protocol.js. Amounts remain public by design: a receipt you cannot show to a third party is not a receipt.

Transaction ID: SHA-256(canon + "\n" + sig_hex). Notch: SHA-256(line 8).

Memo ·Words

1 to 140 UTF-8 bytes, single line. Stored verbatim in the block so both wallets render the exact sentence without an external database or indexer.

Notch

SHA-256 digest of the memo. Recomputed client-side whenever a receipt is viewed. Proves the displayed words are byte-for-byte identical to what entered the block.

Mark · Ref

Optional 64-hex digest. Hash a PDF invoice, archive, or repository commit locally in the wallet; the file stays private while its fingerprint is notarized in the payment.

Units & Fee

1 tTALLY = 1,000,000 notches. Minimum relay and block fee is 0.01 tTALLY, paid directly to the miner who seals the block.

§ 04 · Delivery

From a single receipt to escrowed work.

We ship only what runs in code today and name what comes next plainly.

  1. ● Live now

    Receipts

    Signed payments with a single-line memo, SHA-256 notch, and optional file mark. Browser wallet, local file hashing, block explorer, hourly faucet, Web Worker miner, and standalone CLI node/miner.

  2. Phase II

    Streams

    Block-cadence wages. A payer funds a rate per N blocks; accrued notches belong to the payee immediately if the stream is halted.

  3. Phase III

    Errands

    Mark-bound escrow. Coins lock against a job specification; the worker posts the deliverable’s SHA-256 mark, and the payer releases or the timeout refunds.

  4. Phase IV

    Mainnet

    Genesis after Streams, Errands, and peer-to-peer sync are specified, tested, and reviewed. The canonical receipt format stays unchanged.

§ 05 · Questions

Straight answers.

Is tTALLY the same asset as $TALLY?

No. tTALLY is strictly the testnet coin mined and dripped on this network; it carries zero monetary value. $TALLY is the Robinhood Chain token that backs development toward mainnet, and its contract address is published only at launch.

Where is my private key stored?

Only in your browser’s localStorage as a 64-character hex seed. Signing uses @noble/curves/ed25519 locally on your device. The server receives only the finished public transaction and never sees your seed.

Can I mine against tallychain.org from a terminal instead of localhost?

Yes. Clone Tally-Chain/tallychain, run npm install, and run node miner/miner.js YOUR_TALLY1_ADDRESS. It connects to https://tallychain.org by default, or takes --node http://localhost:8344 if you run your own local node.

What if the recipient is offline when I pay?

They do not need to be online. Once a miner includes your signed receipt in a block, any browser opening that transaction ID recomputes the SHA-256 notch and verifies your signature from the block data.
